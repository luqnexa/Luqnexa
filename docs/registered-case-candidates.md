# 登録済み正式表記をRustモデルへ渡す

2026-10-13。辞書の日本語読み側には英語固有名詞の正式表記が登録されていますが、英字読みの候補には小文字の表記だけが使われる場合があります。従来のケース候補生成は候補プールが既に12件以上だと何も追加せず、新Rustモデルに正解表記を渡せませんでした。

既存辞書の登録済み表記だけを使う`dictionary_case_candidates`を追加しました。先頭16候補から最大16件の正式表記候補を作り、最終的な32件の順位付け前に新Rustモデルへ渡します。機械的なタイトルケース・全大文字の生成は行いません。元候補を維持し、追加候補の辞書スコアは元候補より1低くします。モデルが追加候補を選択するかどうかを決めます。

新しい語・評価用の文章・特定のテスト解答を辞書へ登録していません。文字の読み、言語、単語自体は変更しません。Shiftによる明示的な大文字、単独の既知英単語、URL・メール・コード識別子・ファイルパスは保持します。モデル指定を伴う`convert_with_neural`の実験経路だけで使い、既存Sessionや稼働IMEの確定結果は変更しません。

候補32件でも追加できること、重複が増えないこと、識別子の保持、明示的な大文字指定、単独英単語と混在文の境界をテストしました。Core・AIの関連テストとClippyは通過しました。

同じ旧Rustモデルと実辞書を使った固定validation12文では、第一候補2/12から3/12、正解が32候補内にある件数4/12から5/12になりました。自己点検した合成固定検証であり、一般精度90%や独立した人間の評価ではありません。変更後のWindows x86_64ウォームキャッシュp95は50.70ms。辞書のみ52.44ms・既存文脈50.92msで、ホスト負荷による変動があり、以前の21.5msと比較して速度向上を主張しません。5ms・iPhone実測の達成は未確認です。

学習モデルの重みを変更せず、稼働IMEへ適用していません。次は正解が候補にない文を字句解析・活用候補で扱い、訓練と独立評価を分離して学習を続けます。
