# 文脈付き誤変換の比較学習

2026-10-12、文字n-gramの頻度学習に加えて、正しい候補と誤変換候補を比較するローカルランキングモデルを実装・トレーニングした。文章生成モデルやQwen本体のfine-tuningではない。

`scripts/train-contrast.py` が `models/context-contrast.jsonl` の合成例を読み、pairwise logistic SGDで4096次元の重みを学習する。候補の1〜3文字特徴と、直前文脈の2文字特徴と候補の2文字特徴の組み合わせを使う。FNV-1aによる特徴ハッシュとL2正規化をPythonとRustで共有し、Python/Rustの一致をテストしている。生成する固定小数点モデルは8,200 bytes。

## データと分離

データはこの開発で作成した67組の合成例。個人の入力履歴、他アプリの会話履歴、パスワードは読み取っていない。原文コーパスの追加取得や現行IMEの学習履歴の送信も行っていない。

| 分割 | 組数 | 重み更新への利用 | 学習後の正解数 |
| --- | --- | --- | --- |
| train | 36 | 使用 | 36 |
| validation | 9 | 重みは更新せず、モデルの選択に使用 | 9 |
| test | 18 | 不使用 | 15 |
| regression | 4 | 不使用 | 4 |

train/validation/testで例のグループを分離し、重複とグループ漏洩を拒否する。testやregressionを改変しても学習結果が変わらないことをテストする。モデル選択はvalidationだけを使う。testは見たことのない表現だが、同じ作成者・合成テンプレート系列であり、独立した実世界精度の測定ではない。

既存モデルに新モデルを組み合わせたRust評価は、誤候補に辞書スコアで100点の優位を与え、同じtest+regressionの22組で比較した。従来7/22、新モデルを加えた結果19/22。表示候補の文字列を追加・改変せず、順位だけを変える。これは固定した合成候補比較の結果であり、日常入力全体の精度ではない。

未学習の18組で残った3件は「字を入力して読みを調べる」文脈の `こんな漢字もあります`、「人工知能の研究」の `AIを使いたい`、「推論エンジン」の `AIによる補正`。これらの失敗例を今回の学習へ混ぜて再評価はしていない。次回の拡張では別の新しい評価集合も用意する必要がある。

## 安全な適用範囲

直前の確定文脈が空なら新モデルを使わない。学習例から抽出した対比表現の両側が候補集合にある場合に限り、該当表現を含む候補へ0〜3072点の加点を行う。学習範囲外の候補のスコアは変えない。モデルだけで候補を増やさない。

初期の無制限適用では `任天堂 → ニンテンドウ` と `AIが → アイガ` の回帰を検出した。このため適用範囲と空文脈の保護を追加し、最終版で既存の `scripts/test-context-ai.ps1` を再実行した。固有名詞、AI有効/無効、文脈、個人学習、確定・キャンセル、文字ごとの入力の検証が成功した。

文脈は直近24文字、候補特徴は先頭96文字だけを使い、処理量を制限する。長い文脈・候補で意味を十分に理解できるモデルではない。過去の約束の理解、自由な文章生成、翻訳モデルの学習は今回の実装範囲外。

## 再現と整合性

```sh
python scripts/train-contrast.py
python scripts/test-train-contrast.py
cargo test -p nextime-ai -- --nocapture
cargo bench -p nextime-core --bench context --locked
```

学習スクリプトの既定出力は `.cache/contrast-training/`。再学習だけでは同梱モデルを置き換えない。今回レビュー・検証した成果物だけを `models/` に同梱した。データとモデルのSHA-256、ハイパーパラメータ、分割結果は `models/contrast-training.json` に保存した。

モデルSHA-256: `86c6972a44805664d2e48bdc2f27db5748fd26023d910bd2c37374bd752ad5ce`。

Rustの単体テストとPython4テストに加え、GitHub Actionsのローカル設定へ学習成果物の整合性・分割検証を追加した。公開済みの分割GitHubリポジトリは元の作業ディレクトリと自動同期しないため、この変更のオンラインCI成功を意味しない。

この更新は開発用ソースと同梱モデルの更新。稼働中の登録済みWindows IMEへのインストールは行っていない。実行中の青空文庫自動学習・取得キャッシュ・元データも変更していない。

## 処理時間

Windows x64開発機で `cargo bench -p nextime-core --bench context --locked` を実行した。同梱834エントリ、2000回、ウォームアップ100回の短い入力ではAI有効のp95=0.0317ms。長い候補8件の順位付け単体は500回、ウォームアップ100回でp50=0.4467ms、p95=0.7277ms、最大1.3520msだった。元の文字列生成を多用する実装では長い候補のp95=9.1112msとなったため、特徴のハッシュをUTF-8から直接計算するように最適化した。学習重み・特徴値・評価結果は変えていない。

この測定は開発機上の小規模辞書・合成候補であり、iPhone SE・1億エントリ・描画・LLM処理・消費電力の評価ではない。
