# Luqnexa独自AI（2026-10-12）

標準の候補ランキングを独自の端末内モデルへ切り替えた。Qwenの事前学習済み重みは使わず、設定ファイル・認証キー・補助サーバーを必要としない。F9の無効化を維持し、確定はユーザーのEnter操作だけで行う。

これは候補選択用の統計的分類モデルであり、汎用の文章生成LLMではない。従来の独自文字n-gramモデル・文脈モデル・学習履歴に、小型の対比較分類器を追加している。新しい重みは8,200バイトだが、IME全体・辞書・既存モデル・実行時メモリが8KBという意味ではない。

## 学習と対象

`scripts/train-native.py` は合成の正誤文対を使用し、独自実装のFNV-1a特徴ハッシュと対比較ロジスティックSGDでi16の重みを生成する。初回は学習14対で、その後ユーザー指定30例の誤変換24対を加え、現在は学習38対、検証4対、保持したテスト6対。学習・検証・テストはいずれも全対で正例を優先した。保持テストも近い語彙の合成例であり、独立した一般精度の評価ではない。元の候補スコア・文脈モデルを残し、レビュー済みの連語にだけ追加モデルの影響を限定する。[30例の変更と比較](sentence-suite.md)を参照。

「箸でご飯を食べる」「橋を渡る」「機械を使う」「機会に恵まれた」「AIを愛用している」「愛を大切にする」「Pythonで書くほうがいい」「今日は曇りです」を回帰テストに追加した。必要な候補を辞書に追加したため、改善は分類器と辞書の両方による。8文を丸暗記せず一般化できたという評価にはしていない。ユーザーのMeltype比較は操作例であり、同条件で測定した優劣ではない。

## 入力ミス

4〜24文字の小文字ASCII単語について、QWERTYの隣接キー1箇所の置換、隣り合う文字の入れ替わりを探索する。辞書で英語として確認できた候補だけ追加する。例：`pythpn`・`pyhton` → `python`。これは分類器とは別の制約付き探索処理。既知の英単語や正常なローマ字は補正対象外とし、元のかな読み候補も保持する。F10で入力そのものを選べる。

複数の誤入力、かな配列・フリック位置のずれ、長文内の任意の誤りを自動修復する機能は未実装。確定済み文章の無断書き換えは行わない。

## 検証と再現

`python scripts/train-native.py --check` はモデル・学習報告・対象連語の再現性を検証する。Rustの回帰では8例の一文字ずつの入力・Space・明示確定、意味の異なる候補の対比較、入力ミスと正常入力の保持を検証する。Windows FFIでも8例と標準バックエンド表示を検証し、CIに追加した。

`python scripts/test-native-ai.py --dll <nextime_ffi.dll> --nud <base.nud>` の初回計測は、開発PC・約128万語NUD・200回・warmup20でp50=0.1451ms、p95=0.2514ms、最大0.5037ms。測定はText+Spaceの解析・検索・予測・候補生成・ランキングで、描画・Qwen・ネットワークを含まない。この8例には完全一致の辞書候補があり、全入力での速度やiPhone SE・1億語条件の達成値ではない。詳細は `benchmarks/results/native-ai.json`。

## Qwen互換バックエンド

旧バックエンドはコードを保持し、`LUQNEXA_AI_BACKEND=qwen` を明示したプロセスだけ使用する。標準では独自AIを使用する。起動済みアプリは古いDLLを保持するため、IME更新後に完全終了・再起動が必要。Qwen設定未検出の根本原因を修復したという意味ではなく、標準経路からその依存を除去した。

2026-10-12に `C:/Program Files/NextIME/build-38cab5a53ed8b960` へ更新した。12ファイルのSHA-256と登録先を検証し、インストール済みFFIでも8例・独自バックエンドの表示が成功した。追加の同条件計測はp50=0.1366ms、p95=0.2754ms、最大0.6734ms（`benchmarks/results/native-ai-installed.json`）。通常のTSFホストの別入力・1000回・warmup100ではp95=2.5792ms。これらの測定範囲は異なり、Qwenとの同条件比較ではない。

fmt、clippy、workspace test、releaseビルド、モデル再現性、Windows設定6ケース・TSF統合、固有名詞・文脈・選択学習・文章学習の既存回帰が成功した。CIへ再現性検証とネイティブ8例の検証を追加したが、新しいGitHub Actionsの実行はまだ行っていない。Qwenの自動起動設定を停止スクリプトで解除した。利用中アプリの強制終了はしておらず、実画面の切り替えはユーザーによる再起動後の確認が必要。
