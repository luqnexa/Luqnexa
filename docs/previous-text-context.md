# 直前に書いた文章を使う変換

2026-10-11、文字n-gramが末尾2文字だけを見る制約を補うため、直前96文字の話題の手掛かりと、文脈別の候補選択学習を追加しました。対象はこのLuqnexaセッションで明示的に確定した文章です。他アプリの履歴や、別のIMEで以前入力した文章を取得する処理はありません。フォーカス変更で文脈を消去します。

`models/context-senses.tsv` はAGPLの手作業で作成した語義と手掛かりの対応表です。7組・16表記の同音語について、食事／川、天気／菓子、植物／顔、印刷／美容／宗教などの手掛かりを探します。同じ組で複数の手掛かりがあるときは、より後の話題を優先します。最大3072点の加点だけを行い、候補の文章を生成・変更しません。表記そのもの、または助詞が続く候補を対象とし、人名の「橋本」のような接頭辞一致は対象外です。語の活用・否定・引用・皮肉・複雑な意味理解には対応していません。

個人学習には、読み・選択した表記・直前96文字の重複しない文字2-gramを最大256組、各64回までRAMに保存します。次回の文脈との共通特徴が2個以上で、Jaccard類似度が30%以上の場合にだけ、その文脈で選んだ候補へ加点します。文脈別学習がある読みでは、文脈が変わったときに全体の選択頻度だけで同じ同音語を強制しません。文脈を明示的に消去すると、従来の読みと表記の学習を使います。学習は端末内のみで、ディスク保存・外部送信はありません。F8で文脈別学習も消去し、F9でAI補正を無効化できます。

予測候補を先に表示件数まで削ると文脈に合う低頻度語が消えるため、AI有効時は最大32候補を取得してから順位付け・表示件数への制限を行います。32候補に存在しない語を作る処理ではありません。

実辞書の回帰テストでは以下を確認しました。

| 直前に確定した文章 | 読み | 先頭候補 |
| --- | --- | --- |
| 夕食の準備ができました。 | はし | 箸 |
| 川の向こうに駅があります。 | はし | 橋 |
| 食事の話は終わりです。川を見に行きます。 | はし | 橋 |

テスト62件、fmt、clippy、releaseビルド、従来の日本語・英語混在・文法の回帰テスト、Windows TSFホストテストが成功しました。Windows x64の1,285,626エントリ辞書によるTSFホスト測定は、ウォームアップ100回、1000回の8イベント入力でp50 1.1146ms、p95 1.7218ms、最大2.5865msです。描画・実アプリへのイベント配送・登録操作は含みません。青空文庫の取得が同時に進行している状態での単回測定です。A13・1億エントリ・電力・熱の性能保証ではありません。

639エントリのRAM辞書のベンチマークはモデル初期化4.8351ms、ウォームアップ100回・2000回でAI無効p95 0.0056ms、有効0.0235ms、オンライン8192特徴併用0.0156msでした。条件が異なるため、TSF測定やAI有効／オンライン併用の大小を一般化しません。独立した実入力データセットでの変換精度は未測定です。

新しいWindows配布物は `C:/opencode-rust/target/windows-x64` に作成しています。稼働中IMEへの更新は未適用です。青空文庫の大量学習も引き続き検証用の別成果物を生成します。この変更は大規模言語モデルによる文章全体の理解ではなく、限定的な話題補正とローカルの文脈別選択学習です。

青空文庫の取得・学習については、Codexのこのチャットで毎時確認する監視を設定しました。正常に進んでいる間は通知を出さず、完了・停止・失敗時に結果を知らせます。形式を識別できない作品をスキップした場合は、その件数と未学習作品を区別して報告します。
