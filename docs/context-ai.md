# Context AI 0.1.0 — ローカル候補ランキング

この文書は初期版の記録です。現在は公開例文で学習したモデルとセッション内の個人学習を追加しています。最新の挙動・制限・検証は [AI学習報告](ai-training.md) を参照してください。

2026-10-11。文脈に合う変換候補・誤変換補正の依頼に対し、軽量な統計モデルによる候補の並べ替えを追加しました。大規模言語モデルや文章生成ではありません。

## 動作・操作

Windowsの候補ウィンドウに `AI:on` / `AI:off` を表示します。初期状態は有効で、F9で切り替えます。入力・Space変換の候補をモデルで評価し、ユーザーが選んでEnter等で確定します。モデルが本文を自動確定・送信する処理はありません。F10の原文、F12の日英切替は維持します。

同じIMEセッションで確定した文字列の末尾96文字までをRAMに一時保持します。F9切替、Windowsのフォーカス喪失・サービス無効化で消去します。プロセスを終了しても消えます。ディスク保存、入力からの追加学習、通信、他アプリの会話履歴・文書取得はありません。長期Memoryは未実装です。

モデルは文字の2-gram / 3-gramです。候補全体の文字列と、直前の文脈の末尾2文字を評価します。96文字全体を意味理解する処理ではありません。

実辞書で動作確認した例:

| 操作 | AI有効 | AI無効 |
| --- | --- | --- |
| 「食事に」を確定後に `hashi` をSpace変換 | 箸 | 橋 |
| `せいきででてこない` をSpace変換 | 正規ででてこない | 世紀ででてこない |

これらは開発用コーパスに関連例がある機能試験です。独立した評価データによる精度・汎化性能の証明ではありません。「でてこない」の漢字表記への修正や、すべての意味的な誤変換を解決したとは主張しません。

CLIでは `nextime session --nud FILE.nud` を起動し、`text 食事に`、`enter`、`text hashi`、`space` を順に入力します。`ai` で有効・無効切替、`clear-context` で一時文脈を消去できます。共通APIには `Engine::convert_with_context` を追加しました。通常の `Engine::convert` は従来の変換です。

## モデル・制限

`models/context-corpus.txt` は自作45文、AGPL-3.0-only。SHA-256は `82c0e53937b9c18dfa9fa174aef06b775612d95d241aa3f698b9c88ab1952b9a` です。外部モデル・圧縮ライブラリを使いません。初回利用時に文字n-gramの出現数を集計し、663特徴を保持します。

候補の既存スコアに、学習した2-gram・3-gramのlog-count特徴から計算した補正値を加えます。補正は最大4096点、候補最大32件、各候補の評価最大256文字です。未知のn-gramは加点しません。予測候補も同じ方式で並べ替えます。候補にない単語の生成、ニューラル推論、文節の自動修正、広い会話の意味理解は未実装です。出力文を作り替えず候補の順序を変えるため、誤推定した場合は別候補・かな・原文を選べます。

文脈ランキング用には通常変換から最大32候補を要求してから表示件数へ絞ります。辞書検索の上限、既存の品詞・助詞による安全な候補生成は維持します。非常に広い読みの予測索引や1億エントリでの性能は未検証です。

## 実測

このWindows開発端末、release、639エントリのRAM辞書、`hashi` / 文脈「食事に」、100回warmup・2000反復。モデル初期化0.1211ms、663特徴。AI無効p50 0.0055ms、p95 0.0095ms、最大0.0925ms。AI有効p50 0.0063ms、p95 0.0083ms、最大0.2297ms。背景負荷を固定しておらず、この差からAI有効の方が速いとは判断しません。再測定は `cargo bench -p nextime-core --bench context`。

登録済みDLL、1,285,626エントリ、8イベント（H/A/S/H/I/Space/Down/Enter）のTSFホストは100回warmup・1000反復でp50 0.9694ms、p95 1.9277ms、最大3.9126ms。UI描画、通常キー配送、クラウド、消費電力・熱・iPhone SE・1億エントリは対象外です。
