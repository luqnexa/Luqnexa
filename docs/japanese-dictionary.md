## 予測候補

`yoro`（よろ）から「よろしくお願いいたします」「よろしくお願いします」等、`ose`（おせ）から「お世話になっております」を提示します。最大24件の候補を8件ずつ表示し、上下キーで選んでEnterで確定します。同じ表記の品詞違いで候補枠が埋まる問題を修正しました。共通の日常語・定型句は、ディスク辞書の予測結果に追加して順位付けします。

前方一致を使う予測です。次の単語の推測、個人学習、文脈AI、自由な文章生成は未実装です。Base辞書は最大4ブロックを検索するため、短い読みで全辞書の最頻候補が必ず出るわけではありません。専用の予測索引と活用・接続コストを使う精度改善が今後の課題です。

## 出典・再現

Mozc公式リポジトリの固定リビジョン `18e76511af9371a9a4409b1d13c3e30884b53e9c` の `dictionary00.txt`〜`dictionary09.txt` を取得しました。[上流辞書README](https://github.com/google/mozc/blob/18e76511af9371a9a4409b1d13c3e30884b53e9c/src/data/dictionary_oss/README.txt) に各データの出典・条件があります。

```powershell
python scripts/import-mozc.py
python scripts/test-import-mozc.py
./scripts/build-windows.ps1
./scripts/test-windows.ps1 -SkipBuild
./scripts/elevate-install-windows.ps1 -Action Update

```

インポーターはPython標準ライブラリのみを使います。公開データの取得時だけ通信し、変換時には通信しません。各取得ファイルのSHA-256・元データの件数を `dictionaries/mozc-source.json` に記録しています。入力された文章を辞書取得処理へ渡しません。

元データ1,289,076行を取り込み、長さ上限・制御文字による除外は0行でした。読み・表記に加え、左右の品詞ID、元のコスト、存在する補正フラグを品詞フィールドへ保持します。候補順位用にはコストから説明用の重みを計算します。Mozcの変換アルゴリズムや接続行列を使用しておらず、Mozc相当の精度とは主張しません。自作辞書と結合し、同一読み・表記・品詞を除重複したNEXC成果物が1,285,613エントリです。

MozcのコードのBSD表示だけで辞書全体を説明しません。NAIST/IPADIC、ICOT等の元データの条件も含め、上流LICENSEと辞書READMEの全文を `dictionaries/MOZC-NOTICES.txt` に保存しました。辞書データをAGPLへ変更せず、出典・免責表示をWindows配備へ同梱しています。
