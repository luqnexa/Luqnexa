結論: Phase 1の必須成果物はコードとローカル検証が存在しますが、最初の設計書全体と、その後の「文章を読んで正確に変換する」という要求は未達成です。特に、開発済みの修正と現在登録されているIMEの間に差があります。初期版との独立した同条件の精度比較もないため、改善率を数字で報告することはできません。

## 今回発見・修正した問題

`vscode` を実辞書CLIで入力すると `reading: vscおで`、先頭候補 `vscオデ` となる問題を再現しました。既知の英単語一覧にVSCodeがなく、日本語のローマ字として解析されていました。`vscode` と新名称 `luqnexa` を手作業の英語辞書に追加しました。

圧縮辞書のラッパー `WithCommonPredictions` は共通語を予測にだけ追加し、完全一致検索には追加していませんでした。古い読み取り専用NUDにも追加英単語を利用できるよう、元辞書に一致がない場合、共通辞書の英語・スラングだけを参照する経路を追加しました。元辞書の検索エラーはそのまま返します。日本語の全語を高頻度で上書きする変更は行っていません。表示上の辞書件数は元のNUDの件数で、追加語数は含みません。

`vscode`、`VSCode`、`vscodede→vscodeで`、`vscodeを` の表示・変換を実辞書で確認しました。既に確定した `vscおで` を自動でVSCodeに修復する処理は未実装です。未知の英単語すべてとローマ字日本語を常に正しく判別することもできません。

## 100万回の検査と検証結果

「100万回の思考」を実行したとは報告しません。代わりに、10種類の入力について合計100万回、正規化結果を確認する明示実行のテストを追加しました。release版で5.14秒、全件成功です。10種類を繰り返した安定性検査で、100万種類の入力や100万文の精度測定ではありません。

```powershell
cargo test -p nextime-core --release --test end_to_end million_normalization_checks -- --ignored --nocapture
```

通常のRustテスト67件成功、上記の追加テスト1件成功。Pythonテスト11件、fmt、clippy、releaseビルド、Rust 1.85のcore/dict、実NUDの日本語・AI・英語混在の回帰、Windows TSFホストテストも成功しました。

実辞書で期待する先頭候補を確認した既知の13例は全件一致しました。入力・期待・実際の結果・CLI/辞書SHAを `benchmarks/results/instruction-audit.json` に保存しています。開発に利用した例なので、独立した変換精度評価ではありません。初期版やMozc/Microsoft IMEとの同条件比較もまだありません。

TSFホスト: 約128万エントリ、ウォームアップ100回、1000回の8イベントでp50 1.1078ms、p95 1.6406ms、最大2.6315ms。UI描画・実アプリ配送・登録操作は含みません。641エントリのRAM辞書: モデル初期化4.9576ms、2000回でAI無効p95 0.0085ms、有効0.0149ms、オンライン8192特徴併用0.0163ms。青空文庫取得が同時進行しています。反復回数を増やしたこと自体で精度は上がりません。
