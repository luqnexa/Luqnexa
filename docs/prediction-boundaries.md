# 入力した読みからの予測と英語混在の改善

2026-10-11、ユーザーの「あい(AI)や長文が自動で出るのをやめ、前の文章と入力した読みを使ってほしい」という要望に合わせて予測の範囲を変更しました。

日本語モードでは、ローマ字を日本語に解析した読みで検索します。英語として認識できた入力だけ英語の読みで検索し、普通のローマ字を英単語の前方一致にも流用する処理を止めました。`ai` は「あい」のまま、明示的な大文字 `AI` は既知の英字略語として保持します。`AIによる`、`AIniyoru`、`AIga` はそれぞれ `AIによる`、`AIによる`、`AIが` です。すべての未知の英字列や2文字英単語を自動判別する機能ではありません。

予測補完は読みの追加2文字以内、英語モードでは4文字以内に制限します。補完する表記は12文字以内とし、定型文の登録語は読みを最後まで入力したときだけ出します。英字略語を空白のある長い英語句へ展開する候補も予測から除外します。これにより「よろし」だけで「よろしくお願いします」、「おせ」だけで「お世話になっております」といった全文を出さなくなります。全文の読みを入力して変換する機能は維持します。候補は既存辞書の最大32件から選ぶため、除外後に件数が少なくなることがあります。

「による」「によって」「により」「について」「に対して」「として」は名詞・英字語につながる文法表現として扱い、「に＋夜」や連用形「会い＋による」の組み合わせを抑えます。元のMozc辞書には正当な固有名詞の候補もあるため、名前を一律に削除する処理は行いません。「あい」が愛・藍・名前・英語のどれを意味するか、読みだけから断定しません。

直前96文字の話題の手掛かり、文脈別に学習したユーザーの選択は引き続き順位付けに使います。候補の外にある文章を生成する仕組みではなく、[前の文章を使う順位付け](previous-text-context.md)の対応範囲・限界を維持します。

Rustテスト64件、fmt、clippy、releaseビルド、Rust 1.85のcore/convertテスト、実辞書のAI・日本語・英語混在回帰テスト、Windows TSFホストテストが成功しました。古い全文予測を期待するセッションテストは、短い単語「にほん→日本語」の明示的な選択を確認するテストに改めました。元の辞書には全文登録語を保持しています。

1,285,626エントリのNUDを隣接配置したWindows x64配布DLLのTSFホスト測定はウォームアップ100回、1000回の8イベント入力でp50 1.0365ms、p95 1.6837ms、最大2.2478msでした。実アプリのUI描画・配送、A13、1億エントリ、熱・消費電力は測定していません。独立データセットでの変換精度改善率も未測定です。

新しい配布DLLは `C:/opencode-rust/target/windows-x64` にビルド済みです。稼働中IMEへのインストールはまだ適用していません。青空文庫の自動学習は別プロセスで継続し、終了通知の監視設定も維持しています。
