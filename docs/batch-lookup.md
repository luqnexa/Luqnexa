# 候補を減らさない辞書検索の高速化

2026-10-13。`DictionarySource::lookup_batch`を追加しました。入力順で単独検索と同じ候補を返し、一度に最大128読みを扱います。FileDictionaryは対象ブロックをまとめ、各ブロックを一度ずつ復元して結果を分配します。キャッシュの上限は変更せず、辞書全体を展開しません。共通語・固有名詞の追加と、追記辞書の上書きを保持します。追記語がある読みは従来の上書き処理を使います。

変換の各開始位置に対する部分文字列検索と、誤字候補の英語辞書確認へ適用しました。読みや候補数、文法、順位モデル、スコアは変更しません。バッチを扱えない辞書は単独検索による既定実装を使えます。単独検索との候補・スコア一致、キャッシュ無効時に一つのブロックを一度だけ復元すること、追記による頻度上書き、空検索と上限をテストしています。

Windows x86_64、実辞書47,526,644 bytesと実験用活用差分、同じモデル・診断12例でのウォームキャッシュ測定です。新Rust経路のp95は変更前40.82ms、部分文字列のバッチ化後34.00ms、誤字確認にも適用後25.74msでした。別プロセスの逐次測定なので、OS負荷等のばらつきを含み、厳密な倍率保証はしません。診断の全候補表記・順序・スコアが変更前と一致したことを照合しています。

第一候補の正解2/12、正解が32候補にあるのは7/12で変わりません。改善したのは実行コストであり、学習精度が向上したとは報告しません。通常変換90%、誤字80%、5ms目標は未達です。iPhone・1億エントリ・低電力・発熱・CPU消費の実測ではありません。モデル学習の合否と検索性能を分けて記録し、稼働IMEへの適用は行いません。
