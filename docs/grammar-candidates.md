# 不自然な分割候補の抑制

2026-10-11。添付画像にある「大作仕手ほしいです」「亜成」等の問題を、約128万エントリのNUD辞書で再現し修正しました。

原因は、候補探索が辞書の単語頻度と分割数だけを評価し、品詞・活用の接続を確認していなかったことです。読み全体に一致する登録語があっても、短い漢字・固有名詞をつなげて最大24件を埋めていました。

## 変更

- 読み全体に登録語がある場合は、その登録語とひらがなを候補にします。推測による細切れの組み合わせは追加しません。
- 分割探索では各経路の末尾品詞を保持します。Mozc由来の左右IDは同じ固定リビジョンの品詞定義から解釈します。一般名詞・固有名詞同士の未登録複合、一般名詞から直接「する」への接続などを抑制します。サ変接続名詞から「してほしいです」等への接続を許可します。
- 文中の助詞や定型の活用表現はかな表記を優先し、「シテ」「仕手」等の同音名詞への置き換えを避けます。単独で入力した「仕手」などの登録語は保持します。
- 先頭候補とのスコア差が3072を超える弱い経路を候補表示から除外します。最大24件は上限であり、根拠の弱い候補で埋めません。ひらがな候補は残します。
- `mozc-id.def`を取得・保持するようインポーターを更新し、出典とSHA-256を記録しました。品詞定義は [Mozc公式の固定データ](https://github.com/google/mozc/blob/18e76511af9371a9a4409b1d13c3e30884b53e9c/src/data/dictionary_oss/id.def) に由来し、既存の `MOZC-NOTICES.txt` と合わせて扱います。

対象は `crates/nextime-convert/src/lib.rs`、同`grammar.rs`、`dictionaries/mozc-id.def`、出典JSON、取得スクリプト、回帰テストスクリプト、CI、READMEと本報告です。NEXC辞書本体の内容・エントリ数は変更していません。

## 実測した候補

| 読み | 修正後 |
| --- | --- |
| たいさくしてほしいです | 対策してほしいです／たいさくしてほしいです |
| あなる | アナル／あなる |
| にほんごをにゅうりょくします | 日本語を入力します／ニホンゴを入力します／にほんごをにゅうりょくします |

「はし」の橋・箸・端・かな、単独の「して」の仕手も保持できることを回帰テストで確認しました。画像の最初の例の読みは「あなる」と推定して検証しました。

## 制約

これは保守的な規則による改善です。意味や会話の文脈を理解するモデル、学習済み接続コスト、完全な日本語文法判定は未実装で、すべての不自然な候補を排除したとは言えません。未登録の複合語や省略された助詞のある文章では候補が減ることがあります。完全一致の登録語を優先するため、別の単語境界を持つ同音の文も提示しない場合があります。文節の手動調整・適切な接続モデル・候補品質評価用コーパスが次の課題です。
