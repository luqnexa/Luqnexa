# 同じ候補を保持する探索コストの削減

2026-10-13。候補探索は各開始位置で最大128経路を保持しますが、辞書の候補をつなぐ途中では大量の文字列を生成してから順位を付けていました。最終的に残れない経路でも文字列と品詞のコピーが生じます。

128件の異なる表記・品詞の経路が存在するときだけ、最低スコアを除外判定の下限に使います。新しい経路のスコアがそれより低い場合、文字列を作る前に除外します。同点は除外せず、表記・品詞・分割数のタイブレークを維持します。文脈に依存する既存の接続ボーナスは除外判定前に計算します。途中の256件で再度順位付けし、最終の候補数・beam幅・学習モデルは変更しません。

同点、重複表記、品詞、接続ボーナスを含む経路の展開を、除外しない全展開の参照処理と比較しました。最終4件・32件・128件が一致することをテストしています。Core・変換器の関連テストとClippyも通過しました。

同じ研究モデル・実辞書・固定validation12文の全候補表記・順序・スコアは変更前と一致しました。第一候補4/12、正解候補6/12で変わりません。Windows x86_64ウォームキャッシュの新Rust経路p95は変更前58.28ms、変更後36.04ms。別プロセスの負荷のばらつきを含む測定なので倍率の保証ではありません。速度を改善する実装であり、学習精度が向上したとは呼びません。通常変換90%・5ms・誤字80%は未達です。

比較レポートの日本語がWindowsのstdout文字コードで崩れる問題も修正しました。JSONのASCIIエスケープで記録し、日本語を損なわず読み込めます。既存の比較レポートを元のRustレポートから再生成しています。学習教材・モデル・入力履歴は変更しません。稼働IMEへの適用と予定タスクの再開は行っていません。
